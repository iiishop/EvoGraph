# 工程设计与运行语义

## 分层

`domain` 定义可持久化结构与确定性规则；`application` 是用例；`infrastructure` 负责 SQLite、仓库扫描和用户触发的验证进程；`providers` 只翻译模型协议；`agent_tools` 是可发现的能力插件；`transport` 提供 HTTP 和 pywebview 两个薄入口。

前端由侧边栏、项目条目、工作区、图、节点、连线、详情、输入框、问题提示、附件选择器、资料预览、架构页等独立组件组成。共享状态在 composables，页面组合在注册表中。组件不直接依赖桌面桥接，统一调用 `api/client.ts` 与 `api/agentStream.ts`。

## 单点扩展

| 扩展内容 | 扩展入口 |
| --- | --- |
| Agent 新能力 | 在 `agent_tools` 新增模块，用 `@tool` 声明 Pydantic 参数、处理器、显示标签、视觉效果；启动时自动发现 |
| Provider | 在 `providers` 新增注册模块，声明配置字段与协议适配；设置表单由字段描述生成 |
| 工作区视图 | `frontend/src/lib/workspaceViews.ts` 一条配置，同时生成标签与内容 |
| 侧边栏页面 | `frontend/src/lib/navigation.ts` |
| 上传格式 | `application/attachments.py` 中通过 `@parser` 注册解析器；前端接受类型由后端提供 |
| 调查规则 | `domain/policies.py` 的变更类别注册表 |
| 连线外观 | `frontend/src/lib/edgeKinds.ts` |
| 架构组件角色 | `frontend/src/lib/architectureRoles.ts` |
| 外部验收 | `AcceptanceService` 统一导出契约、导入报告和流转状态，外部 Agent 复用同一接口 |
| 网页搜索服务 | `web_search` 新增一个 `@register` 模块，声明搜索/提取能力与配置字段，设置 UI 自动生成 |

这些保证常见同类扩展不用重复改分派逻辑。新增跨层业务概念仍需调整模型与对应展示，不承诺任何需求都只改一行。

## 增量执行与一致性

Agent 接收当前项目、当前架构、资料目录与用户选中的多模态引用。流式参数达到完整 JSON 后，经插件参数校验即执行；不会等待整轮叙述完成。未知工具、非法参数和图约束错误返回模型修复。运行器不写死里程碑操作顺序。

每项目互斥锁与 SQLite 修订 CAS 防止覆盖更新。每个工具提交一次，界面收到提交后的快照。取消会等待已启动的写入完成，再释放锁；因此取消保留部分修改，不回滚已经显示的节点。Agent 调查没有固定的轮数、工具数、源码文件数或网页请求数上限；用户可以主动停止，系统也会在取消时保留已完成的修改。

历史行为修订、架构修订与证据保留。目标与规划修订分开：修改行为契约才需要新目标版本。旧计划接口保留兼容，当前 UI 只走流式工具，不走讨论/草案确认。

## 两种图、一个目标

里程碑图是执行前置关系 DAG：必须有理由，引用必须存在，不能重复、自环或构成环。实现、迁移、验证是前置关系的解释，不把调用关系或共同修改误作前置边。资源冲突独立计算，不伪装成图依赖。自动布局只决定摆放，不添加语义依赖。传递边可能表达独立契约，系统不未经审查自动删除。

设计图使用结构化节点、带标签的边。架构页保存组件边界、技术栈、选择理由和决策；状态图可以有循环。里程碑通过组件 ID 关联架构。架构更新保留版本、拒绝删除仍被引用的组件、禁止在任务已领取时修改，并让现有任务重新审查。验收证据同时绑定行为修订、基线和架构修订。

目标是图上方独立的完成标识，不占用 PR 节点。并非所有测试工作都不适合 PR：新增测试设施、真实服务接入仍可独立交付；单纯“最后验收一下”不应被建模为交付里程碑。

架构可视化参考 [archify](https://github.com/tt-a1i/archify) 的结构化图源、确定性渲染与可追踪版本思路。本实现使用本项目的数据模型和 Vue Flow，并未安装或嵌入 archify，也不执行其远程代码。

## 资料与边界

上传经解析验证后，元数据、二进制与审计在同一 SQLite 事务提交。上传的图片重编码为 PNG；模型输出仅能生成声明式图数据，不能注入可执行 HTML/SVG。图片仅随用户选中的引用发送；文档可由 Agent 工具分页读取。当前有文本截断、文件数量及体积上限，详见 README。

布局使用 ELK 分层与交叉最小化，固定左右端口。里程碑保留用户选定的原始贝塞尔曲线渲染，ELK 的正交路由仅参与布局计算，不直接画成折线。架构图使用独立的曲线边组件，绑定显式 in/out 端口与 Vue Flow 实际坐标；回边绕至画布下方，避免穿过组件。手动布局用几何模块消除重叠。复杂图不保证零交叉。

图上的进度与实际仓库执行区分：当前 Agent 可读源文件、编辑规划、维护架构与设计图，不负责实现代码。用户运行的验证命令不经过 shell 拼接；结果需要匹配当前完整基线，运行期间文件变化会拒绝该结果。

## 源码、调查与轻量验收

基线刷新同步生成 `source_milestones` / `source_diagram`，与待交付 milestones 和行为契约分开持久化。稳定 ID 来自目录名摘要，重复扫描幂等，已消失的源码组件在现状图中移除，不改变设计版本。现状关系表示解析到的导入，绝不自动成为执行前置依赖。源文件不执行。

`resolve_investigation` 要求引用本轮实际读取的文件与匹配的哈希、基线。它证明 Agent 使用了哪些输入，不机械证明结论一定正确；判断不足时应向用户提问。Agent 调查记录随基线变化失效。

验收由外部 Agent 执行：复制验收提示词、粘贴报告，全部行为通过后完成并释放。详见 verification-integration.md。历史 LightCheck 数据仅保留兼容。

网页工具与供应商解耦：`web_search` 使用注册的搜索提供方，新安装默认使用无需密钥的 Bing RSS 基础搜索；设置可选择 Tavily、SearXNG 或关闭搜索。`web_fetch` 独立读取公开网页，不依赖搜索服务，支持 HTML、文本、XML 和 JSON，不执行脚本、不登录。原有 `web_extract` 保留供支持提取的服务使用。各工具保存可引用的来源 ID，同轮重复请求复用结果，无固定请求次数预算。

任意网页读取校验 DNS 地址并固定连接目标，每次重定向重新校验，禁止私网和带凭据地址；响应限制为 2 MB，返回正文限制为 20000 字并标明截断。Bing 是公开搜索入口，可能限流或要求验证；失败时明确报告，不伪造结果。SearXNG 地址是用户显式配置的服务端地址。

## 依赖自动约简

Agent 工具允许冗余前置边正常写入；一轮编辑结束后 GraphEditor.finalize 调用
`domain/dependencies.py`，自动删除存在替代路径的直接边。启动读取现有项目和旧式整图规划
也复用同一函数。只删除冗余边及其理由、类型字段，保留完整可达性；清理记录保存在事件中。
领取条件检查完整祖先链，防止约简后遗漏已失效的间接前置证据。


## 当前基线的已实现里程碑

`source_index` 只提供架构目录与静态导入参考，不再把目录生成为里程碑。
Agent 通过 `reconstruct_baseline_milestones` 工具读取代码后，按独立交付能力倒推目标、范围、行为契约及前置依赖。
每项行为携带本轮实际读取的源码引用；`BaselineMilestoneService` 校验读取回执、当前基线与完整 DAG，并复用传递约简规则。
整组校验成功后原子替换 SRC 图，稳定 ID 保留位置，不修改计划、目标或验收记录。旧目录节点读取时自动退出里程碑视图，架构扫描结果保留。

SRC 节点状态为 `IMPLEMENTED`，表示源码推导的已实现能力，不表示历史 PR 或正式验收 PASS。
它们使用独立的 `source_behaviors` 契约，不计入待交付验收进度。每个节点绑定推导基线；仓库刷新后保留旧推导并明确提示待更新。
前端 `useBaseline` 统一协调刷新与 Agent 倒推；新基线刷新成功后自动启动倒推，未配置 Provider 时提示配置。
画布提供重试/重新倒推入口，SRC 与计划节点共用依赖布局、曲线和左右连接点；详情展示能力契约、逐项源码依据与调查局限。
源码读取工具支持分页续读，避免长文件只检查开头。未修改图不再自动构造问题；需要提问时由 Agent 显式调用有准入规则的工具。

SRC 能力也可以作为计划里程碑的严格前置依赖。依赖约简在 SRC 与计划节点组成的完整 DAG 上执行；SRC 前置以当前完整源码基线和行为契约证明“能力已存在”，不会伪造外部验收证据。计划节点仍按正常领取、外部制作和外部验收流程执行。

类图使用固定 `class_model` 标识持续维护。类图可以是 `source`、`mixed` 或 `design`：`source` 只收录源码事实，`mixed` 同时展示代码和设计，`design` 表示整图尚未由源码证明。未实现的类或成员必须出现在 `design_elements`，系统会在导出的 PlantUML 中写入 `DESIGN` 标识；源码更新后只有再次读取到真实实现，Agent 才能移除标识。
