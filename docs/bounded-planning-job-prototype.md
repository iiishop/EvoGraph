# Bounded planning job: offline vertical slice

This prototype adds opt-in, explicitly authorized planning jobs. Ordinary turns retain their five-call default. It is not a coding-agent integration, a semantic-quality result, or authorization for a real provider run.

## Scope

- One user intent/source/message per job; internal execution phases have distinct durable IDs
- Fresh jobs route the retained design again, even when feedback text is identical. An old held manifest or timeout is never an automatic continuation
- A clean, closed phase may reuse its exact executable schedule and compiler checkpoints. Old generation content/audit, call receipts and source lineage are preserved; separate review attempts append their own audit
- Every request admission and dispatch transition is checked under the same SQLite writer transaction as the persisted candidate/review call metrics. Aggregates are derived from those metrics, not independent spend counters
- Calls admitted before cancellation, process failure or uncertain dispatch remain charged. A terminal failed/timeout receipt cannot be mutated or followed by another call in that phase
- Normal scheduler, projected generator tools, compiler, deterministic harness, semantic review and atomic publication are reused
- If generation becomes ready but its phase input budget prevents semantic dispatch, the genuine deterministic budget-exhausted harness receipt admits one existing review-only attempt. No historical review is invented

## Limits

Explicit job ceilings are at most 3 phases, 12 calls and 1,179,648 input bytes. Limits must also fit the selected phase count. Defaults in the opt-in form are 1 phase, 5 calls and 393,216 input bytes, with an explicit confirmation reset whenever input, source pins or limits change.

Each generation phase keeps 5 calls / 393,216 total input bytes. Review-only phases keep their existing one-call limit. Every request keeps 163,840 input bytes / 98,304 output bytes / 180 seconds. No provider or model settings are changed.

Automatic continuation ends on a held/uncovered/invalid schedule, invalid tool/output, provider timeout, incomplete/uncertain request, question, stale state, no safe progress, unsuccessful review, cancellation or aggregate exhaustion. It does not replenish router-repair quotas or run a semantic-repair loop. A crash-open phase cannot resume or dispatch again; it can be cancelled before a new explicit job. Direct adoption of an experimental predecessor remains blocked by the existing experiment gate; that predecessor needs its separate explicit repair flow. A new substantive user direction is a new source/job. Budget exhaustion requires new explicit authorization rather than silently increasing limits.

## Visible workflow

The panel shows retained and newly saved compiler checkpoints, completed/runnable/held/remaining generation units, phase and aggregate use versus authorization, incomplete token usage, typed stop reasons, cancellation and eligible exact-pin continuation. Remaining call count is only a lower bound. The current prototype accepts plain-text bounded starts; rich references/attachments remain available through ordinary planning and are clearly blocked in bounded mode.

## Offline verification

`tests/test_bounded_planning_job.py` covers nine fake calls over two phases and normal atomic apply; a three-phase genuine review-budget boundary; stable source/message and checkpoint lineage; immutable old phases; aggregate call/byte/phase exhaustion; persisted cancellation before and after dispatch; cancellation after atomic apply; duplicate start; stale start/candidate pins; crash-open refusal; terminal timeout ledger protection; no-progress; partial usage; retained-five/new-seven arithmetic; and fresh jobs after discard or applied baselines.

The fake provider demonstrates orchestration and deterministic integrity only. It does not demonstrate that a model follows the instructions or that the QA55 email/ownership defects are repaired.

`tools/preflight_bounded_job.py` imports an explicitly supplied frozen snapshot into a new temporary database and cancels before its first provider dispatch. It checks exact retained histories, existing holds, the fresh router path, unchanged source text, retained checkpoints and unchanged canonical state.

`tools/preview_bounded_job.py --check` checks a native synthetic preview without opening a GUI. Without `--check`, the clearly labeled synthetic window uses the real application and a hard fake provider in a new temporary profile. SQLite access outside that profile, credential-manager and provider-adapter imports, and non-loopback socket connections are rejected. No provider configuration or real profile is copied. Its initial five checkpoints are generated by the real compiler using fake calls; a user can then exercise a nine-fake-call job through the normal UI.

No paid call, publication, commit or upload is part of this prototype's verification.
